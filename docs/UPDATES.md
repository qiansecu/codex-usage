# 自动更新与故障恢复

从1.1.0起，独立统计入口会在启动客户端前检查本仓库的正式Release。首次安装仍显示重启确认；更新不会主动关闭正在工作的客户端。

## 使用方式

正常使用桌面或开始菜单的统计入口即可。成功检查后6小时内不重复访问GitHub；断网、下载或校验失败会继续启动已安装版本。没有正式Release时也保留现有版本。更新检查与下载有超时，不使用Git、GitHub登录或用户Token。

仅接受固定仓库qiansecu/codex-usage的稳定版本，忽略草稿、预发布及不高于本地的版本。先核对GitHub提供的压缩包SHA-256，再检查包内文件清单、大小及每个文件的哈希。所有验证通过后才替换源码，保留回退副本。校验可以发现下载损坏，不是独立于GitHub的作者签名。

客户端或记录中的统计进程仍在运行时跳过更新。Git工作副本也跳过，以免覆盖维护者的代码。首次setup会记录源码基线；更新时发现源码被编辑、缺失，或新文件与用户文件冲突，就保留本地文件并暂停自动替换。请勿删除基线来强行接受更新。

设置环境变量CODEX_USAGE_AUTO_UPDATE=0可以停用自动检查。下次启动时生效；不需要修改官方客户端配置。

## 回退与限制

更新应用过程中发生文件写入错误，会尝试恢复备份。若更新后本次启动报错，入口会恢复旧源码并记住失败版本，避免再次自动安装它；请保存工作、完整退出客户端，再用统计入口启动旧版。回退不会自行关闭客户端或再次重启。

回退也会核对文件，更新后新增的用户修改不会被强行覆盖。备份和诊断记录位于app/runtime-updates/，不能上传或公开分享。

当前实现没有断电时完整目录切换的保证，也不会在运行数小时后自动回退。生成的静默EXE、快捷方式、个人设置与会话均不在更新包内；未来若需要更换EXE本身，应按该版本说明手动重新安装。

## 自动恢复与自动适配

通信超时或页面上下文短暂切换时，仅在原来核验过的连接上重试幂等的界面读取、渲染，最多3次。不会自动选择另一端口或另一窗口。错误会记录命令名称，不记录命令中的页面内容。

首页没有会话时，注入与数据往返成功即可确认启动，不再等到已有统计数值才算成功。启动等待为60秒，ready.json记录本次健康连接；它不代表每一项原生界面结构都已兼容。工作区控件出错时会独立停用，避免影响Token统计。

这些处理能覆盖部分启动时序问题。原生DOM、内部接口或本地记录格式发生未知变化时，仍需要维护者适配并发布新的正式Release。

## 维护者发布

1. 修改源码及app/version.json中的三段版本号，更新CHANGELOG和实际验证范围。
2. 运行本地检查、公开文件检查并核对提交使用获准的noreply署名。
3. 推送对应v版本号标签，例如v1.1.1。Release工作流会重新执行检查，然后生成带manifest.json的codex-usage.zip并发布。
4. 检查Release工作流结果与压缩包是否存在。仅推送main不会发布自动更新；GitHub默认的Source code.zip也不能替代带清单的更新包。

打包使用scripts/build-release.ps1，可指定一个新的输出目录；不会复制运行记录、本地设置或客户端资源。GitHub正式Release接口参见[官方文档](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)。
